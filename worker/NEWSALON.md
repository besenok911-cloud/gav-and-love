# Розгортання нового салону

Один салон — один воркер, одна база, свої бакети, свої секрети. Нижче — повний шлях від
порожнього місця до салону, який приймає записи. Приблизно година, якщо прайс уже зібраний.

Команди для **Windows PowerShell**: там немає `&&`, команди пишуться окремо.

---

## 0. Що знадобиться

| Що | Де взяти |
|---|---|
| Акаунт Cloudflare | краще одразу власниці салону — воркери між акаунтами не переносяться |
| Увімкнений R2 | панель Cloudflare → R2. Це платіжна опція, з CLI не вмикається |
| Telegram-бот | @BotFather → `/newbot` |
| Google Calendar | не обов'язково (див. крок 6) |
| Репозиторій | форк цього; статику доведеться наповнити контентом салону |

## 1. База

```powershell
cd <репозиторій>\worker
```

```powershell
npx wrangler d1 create <ім'я-бази>
```

Ідентифікатор із відповіді вписати у `wrangler.toml` → `[[d1_databases]] database_id`.

```powershell
npx wrangler d1 execute <ім'я-бази> --remote --env="" --file schema.sql
```

Створюються всі 16 таблиць, 20 індексів і один рядок у `companies` з `id=1`. **Таблиці майстрів
і послуг лишаються порожніми — так і має бути.** Доки немає жодного активного майстра, форма
запису не пропонує часу: ненастроєний салон не повинен приймати записи.

Назву салону поміняти під свою:

```powershell
npx wrangler d1 execute <ім'я-бази> --remote --env="" --command "UPDATE companies SET name='Назва салону', slug='nazva' WHERE id=1"
```

## 2. Бакети

```powershell
npx wrangler r2 bucket create <ім'я>-photos
```

```powershell
npx wrangler r2 bucket create <ім'я>-backups
```

Обидва вписати у `wrangler.toml`. **Прив'язка до неіснуючого бакета валить усе викочування**,
тож спершу бакети, потім деплой.

## 3. Адреси сайту

У `wrangler.toml` → `[vars]`:

- `ALLOW_ORIGIN` — origin сайту, з якого дозволено звертатися до воркера
  (наприклад `https://<акаунт>.github.io`, без шляху);
- `SITE_URL` — повна адреса сайту, її бот підставляє у посилання клієнтам.

Помилка тут виглядає як «сайт не працює»: браузер упреться в CORS, а бот слатиме клієнтів
на чужий сайт.

## 4. Секрети

```powershell
npx wrangler secret put ADMIN_TOKEN --env=""
```

```powershell
npx wrangler secret put PLATFORM_TOKEN --env=""
```

- **`ADMIN_TOKEN`** — аварійний пароль власника до CRM. Працює як пароль на вході (логін будь-який),
  сесію видає звичайну, її можна завершити виходом. Це єдиний спосіб зайти в порожню базу.
- **`PLATFORM_TOKEN`** — ключ **оператора** до нічних дампів (`/admin/backup-*`) і до повного
  `/health`. Дамп містить телефони клієнтів, хеші паролів і живі токени сесій, тому власниці
  салону він не передається. У CRM кнопки для нього немає і не буде.

Згенерувати випадкове значення:

```powershell
-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 40 | % {[char]$_})
```

## 5. Telegram

```powershell
npx wrangler secret put TELEGRAM_BOT_TOKEN --env=""
```

```powershell
npx wrangler secret put TELEGRAM_CHAT_ID --env=""
```

Після викочування — кнопка в CRM «Підключити бота» (реєструє вебхук). `chat_id` беруть із
`https://api.telegram.org/bot<TOKEN>/getUpdates`, написавши боту будь-що.

## 6. Google Calendar — за бажанням

```powershell
npx wrangler secret put CALENDAR_ID --env=""
```

```powershell
npx wrangler secret put SA_EMAIL --env=""
```

```powershell
npx wrangler secret put SA_PRIVATE_KEY --env=""
```

Без них салон працює: зайнятий час рахується з власної таблиці записів. Календар потрібен тоді,
коли майстри хочуть бачити день у телефоні й вручну блокувати години. **Якщо календар є, він стає
єдиним джерелом зайнятості** — ручні блокування в ньому враховуються, а таблиця вже не опитується.

## 8. Власниця салону

Ручки «створити власника» у воркері немає навмисно: це крок розгортання, а не дія, доступна ззовні.

```powershell
node tools\owner-sql.js vlasnyk "Ім'я власниці" > owner.sql
```

Пароль друкується в консоль **один раз** — збережіть і передайте. Далі:

```powershell
npx wrangler d1 execute <ім'я-бази> --remote --env="" --file owner.sql
```

```powershell
Remove-Item owner.sql
```

При першому вході CRM попросить змінити пароль.

## 8a. Акаунт підтримки (за бажанням власниці)

Якщо салон хоче, щоб розробник міг правити сайт і налаштування після передачі — власниця
заводить йому **іменний** акаунт у «Доступи» з роллю **Підтримка** і задає пароль сама.

Акаунт мертвий доти, доки вона не натисне «Підтримка» в CRM і не відкриє доступ на 2 години,
8 годин, добу або три. Доки вимикач вимкнений, розробник не бачить і не може нічого — навіть
знаючи пароль. Що саме він зможе і чого не побачить — написано людськими словами просто в тій
модалці; окремим прапорцем вмикається право правити послуги і ціни.

Міграцію `0003_support_log.sql` треба застосувати в будь-якому разі — журнал обов'язковий.

## 8b. Випуски оновлень

Пуш у `main` не викочує нічого. Код потрапляє в салон тільки прогоном `release.yml` і тільки
після того, як власниця натисне «✅ Випустити» в чаті салону. Налаштування — один раз, покроково
в `worker/HANDOVER.md`, розділ «Як розробник випускає оновлення»: токен Cloudflare з правами на
Workers + D1 + R2, секрет `DEPLOY_TOKEN` (однаковий у GitHub і у воркері), змінна `WORKER_URL`,
міграція `0004_releases.sql` і перемикання Pages на `build_type=workflow`.

Доки Pages публікується з гілки, прогін свідомо падає: інакше вся CRM їхала б повз дозвіл.

## 9. Наповнення

У CRM, під власницею або під `ADMIN_TOKEN`:

1. **Майстри** — доки список порожній, записів не буде.
2. **Послуги й прайс** — жодних значень за замовчуванням не підставляється.
3. **Налаштування** — лояльність, нагадування, тексти.

## 10. Приймання

```powershell
curl.exe -s -H "Authorization: Bearer <PLATFORM_TOKEN>" https://<воркер>/health
```

`/health` без токена віддає лише версію і бази не торкається — годиться для монітора доступності.
З токеном показує все, що потрібно для підтримки, і **жодних даних клієнтів**: версію, чи
під'єднані календар і бот, чи є бакет бекапів, які таблиці на місці, скільки майстрів, послуг,
записів, коли був останній бекап.

Ознаки, що щось не доробили: `"ok": false`, `missing_tables`, `"masters": 0`,
`"жодного бекапу ще не було"`.

Далі перевірити руками: відкрити сайт, обрати час, записатися, побачити запис у CRM і повідомлення
в Telegram, спробувати записатися вдруге на той самий час — має відмовити.

## Після запуску: як оновлювати

Пуш у `main` **не викочує нічого**. Єдиний шлях у салон — прогін
`.github/workflows/release.yml`, і тільки після того, як власниця натисне «✅ Випустити» в чаті
салону. Токен Cloudflare лежить у секретах репозиторію салону, тож доступ до її акаунта
Cloudflare для підтримки не потрібен. Налаштування один раз — розділ 8b і `worker/HANDOVER.md`.

Версія збірки: константа `VERSION` — це дата великої зміни і піднімається руками, а `BUILD` —
штамп конкретного випуску (`r<номер>-<sha7>`), який прогін ставить сам і по ньому ж перевіряє,
що поїхав саме той код. Обидва видно в `/health`. Коли салон, яким володіє вже не розробник,
поводиться дивно, перше питання — який там `BUILD`, і дізнатися це більше нізвідки.
